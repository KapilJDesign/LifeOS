# Life OS Chrome extension

A small Manifest V3 extension that saves the page you are on, a link, or selected text to Life OS in one click. It has no build step and no backend: it opens the Life OS app at `/capture` with the content in the query string, and the app saves and organises it.

## Load it (unpacked)

1. Start Life OS: from the project root run `npm run dev` (it serves `http://localhost:5173`).
2. Open `chrome://extensions` in Chrome (or Edge, Brave, or any Chromium browser).
3. Turn on **Developer mode** (top right).
4. Choose **Load unpacked** and select this `extension/` folder.
5. Pin the **Life OS: Save** icon from the puzzle-piece menu so it is always one click away.

After you edit a file, press the reload icon on the extension card. There is nothing to compile.

## Use it

| Action | What is saved |
|---|---|
| Click the toolbar icon, then **Save to Life OS** | The current tab's URL and title, any text you had selected, and an optional note |
| Keyboard shortcut `Cmd+Shift+L` (macOS) or `Ctrl+Shift+L` (Windows, Linux) | Opens the same popup. Change it at `chrome://extensions/shortcuts` |
| Right-click selected text, then **Save selection to Life OS** | The selection, plus the page URL and title |
| Right-click a link, then **Save link to Life OS** | The link's URL |
| Right-click anywhere on a page, then **Save page to Life OS** | The page URL and title |

Life OS opens in a small window (or a new tab, see settings), saves the item straight away and shows it being organised. If you have already saved the same URL, Life OS says so and does not create a duplicate.

## Settings

Open the extension's **Settings** link in the popup (or `chrome://extensions`, then **Details**, then **Extension options**).

- **App URL**: where Life OS runs. The default is `http://localhost:5173`. Set it to your deployed address (for example `https://life.example.com`) when you have one. Only `http` and `https` addresses are accepted.
- **Open in a new tab**: uses a normal tab instead of a small window.

## How it hands off

The extension builds this link and opens it:

```
<app url>/capture?src=extension&url=<page url>&title=<page title>&text=<selection>&note=<your note>
```

The app's `/capture` route reads the query with `parseCaptureQuery` and calls the single inbound function `ingestCapture` (see `src/lib/capture/inbound.ts`), exactly as the in-app capture bar, the Android share target, the bookmarklet and the iOS Shortcut do. The link format is shared: `capture-link.js` here and `parseCaptureQuery` in the app are checked against each other by `src/lib/capture/inbound.test.ts`, so a change to one that breaks the other fails the test run.

Nothing is sent to any server other than the Life OS app you configured. Selected text and notes travel in the query string of that single navigation, and are truncated to 2,000 characters.

## Permissions, and why

| Permission | Reason |
|---|---|
| `activeTab` | Read the current tab's URL and title when you click the toolbar icon |
| `scripting` | Read your current text selection from that tab, only when you click |
| `contextMenus` | Add the three right-click entries |
| `storage` | Remember the app URL and the tab preference (synced with your Chrome profile) |

There are no host permissions and no content scripts, so the extension cannot read pages you have not explicitly acted on.

## Files

| File | Purpose |
|---|---|
| `manifest.json` | MV3 manifest, permissions, keyboard command |
| `popup.html`, `popup.css`, `popup.js` | Toolbar popup: page preview, selection, note, save |
| `background.js` | Service worker that registers and handles the context-menu entries |
| `capture-link.js` | Pure helpers shared by every entry point: build the deep link, normalise the app URL, skip browser-internal pages |
| `capture-link.d.ts` | Type declarations so the app's tests can import `capture-link.js` |
| `options.html`, `options.js` | Settings page |
| `icons/` | Placeholder icons generated by `scripts/generate-icons.mjs` at the project root |

## Known limits

- Pages Chrome does not allow extensions to script (`chrome://` pages, the Chrome Web Store, the new-tab page) cannot be saved from the popup. The popup says so.
- A very long selection is truncated, and very long URLs can exceed browser limits for a navigation; this is unlikely for normal pages.
- The extension is not yet packaged for the Chrome Web Store. Publishing needs a store listing, a privacy statement and a final icon set.
- Firefox and Safari are not covered. The same code would need a small manifest change for Firefox, and a Safari web extension wrapper for Safari.
